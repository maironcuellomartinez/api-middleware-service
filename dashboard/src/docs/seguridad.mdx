# 🔒 Auditoría de Seguridad — DeepSeek Code en Escenario OS Comprometido

**Modo de madurez aplicado:** Beta (defecto, equilibrado)

---

## 1. Resumen Ejecutivo

DeepSeek Code expone herramientas de alto privilegio (escritura, lectura, ejecución de comandos) que, en un escenario donde el sistema operativo del usuario está comprometido, convierten al asistente en **un vector de ataque lateral**. El atacante puede modificar archivos de configuración del agente para inyectar instrucciones maliciosas, leer archivos arbitrarios del sistema sin restricción (ripgrep_search), y editar archivos del proyecto sin confirmación (edit_file). Las defensas actuales son **parciales** (protección de ruta en algunas tools, listas de comandos peligrosos, confirmación en execute_command) pero presentan **5 brechas críticas** y **7 de alta severidad** que permiten daño significativo.

**Decisión: NO-GO condicional** — No se debe desplegar en entornos con datos sensibles sin aplicar las remediaciones inmediatas. Tras implementar el plan propuesto, reevaluar.

## 5. Riesgos Residuales Top 3 (Aceptados con Mitigación Parcial)

1. **Prompt injection persistente**: Aún con defensas, un atacante con acceso al sistema puede modificar archivos de configuración en rutas no protegidas. Mitigación: checksums + readonly en archivos core. Riesgo aceptado: medio (requiere acceso root para desactivar protección).
2. **Exfiltración vía ripgrep_search**: Si se restringe a solo proyecto, el atacante puede leer archivos dentro del proyecto que contengan secretos comprometidos (como tokens temporales). Riesgo aceptado: bajo, porque el proyecto debería tener sus propios controles de acceso.
3. **By-pass de confirmación por confianza del usuario**: Un usuario descuidado puede ignorar advertencias. Mitigación: educación + logs auditables. Riesgo aceptado: inherente a herramientas CLI de alta potencia.

## 8. Nota Final sobre el Escenario OS Comprometido

Este análisis asume que el atacante **ya tiene acceso a la sesión del usuario legítimo**. En ese contexto, ninguna herramienta diseñada para ser útil al usuario puede ser completamente segura — el atacante podría incluso **reemplazar el binario de deepseek-code por una versión troyanizada**. Las defensas propuestas (confirmación, restricción de ruta, integridad de configuración) elevan significativamente el costo del ataque, forzando al atacante a usar técnicas más ruidosas (reemplazar binarios, modificar procesos) que son detectables por EDR/antivirus. El objetivo es **no ser el eslabón débil**: DeepSeek Code no debe facilitar el daño lateral.
